# B4：B300 单卡 TPOT 追平并超越 vLLM（sm_103）

> 用户 2026-10-19："先调优 B300 单卡性能要优于 vllm"。基线 `test/qwen3/2026-10-19/bench_b300_1`：dinfer TPOT 落后 20–35%（c1 1.5 vs 1.2 ms；c8-long 2.2 vs 1.4），TTFT 领先 2–4×，c32 吞吐持平。

## 根因（第 0 轮 nsys，`scripts/dev/b300_nsys_decode.sh`）

decode 一步 GPU 忙 ≈ 1.5 ms（= TPOT，host 已被图掩盖）。按 kernel 分（c1，每层一次）：

| kernel | avg µs | 带宽下限 µs | 结论 |
|---|---|---|---|
| rmsnorm（×2） | 3.7 | ~0.5 | 单 block 256 线程 × 4 轮串行标量访存，**延迟主导** |
| silu_and_mul | 6.9 | ~0.5 | 单 block × 12 轮串行标量访存 |
| qkv_post | 6.1 | ~0.5 | 4 warp 轮流处理 24 头，每 warp 6 轮串行 |
| gqa_decode_v2 | 7.7（c8-long **23.4**） | c8-long ~5 | splits 封顶 8，c8 只 512 block / 148 SM，在飞 KV 读不够 |
| 4 × cuBLASLt GEMM | 4.1–6.7 | 0.6–1.9 | M=1 下 nvjet 也是延迟主导，但不是我们能改的（第 2 轮再看 heuristic） |

非 GEMM 五个 kernel ≈ 28 µs/层 ≈ 0.78 ms/步，而它们的带宽下限之和 < 3 µs/层。**B300 HBM3e 单次访存延迟比 4090 高，串行访存链在 B300 上更吃亏**——这就是"4090 领先、B300 落后"的原因，与 Blackwell 特有 kernel 无关。

## 目标

`bench_compare.sh` 四组（c1 / c8 / c32 / c8-long）TPOT 全部 ≤ vLLM nightly（B300），且 4090 四组不退化（> 3% 即不合入）。

## 环境

B300 GPU 6 跑 dinfer（`scripts/dev/restart_dinfer_b300.sh`），GPU 7 跑 vLLM（`scripts/dev/vllm_nerdctl.sh run 7 8013`，**用完 stop**）。4090 回归：`scripts/dev/remote4090.sh` + `restart_dinfer.sh` + `bench_compare.sh`。

## 观察方法

- `scripts/dev/b300_nsys_decode.sh <tag> <并发> <prompt_len>`：kernel 耗时表（改前后对照）。
- `cargo test -p dinfer-kernels -- --ignored` 中 norm / silu / qkv_post / gqa_decode 的 ref 测试（两卡都跑）+ `ops_parity.sh`。
- `bench_compare.sh test/qwen3/<日期>/bench_b300_N "改动"` → CSV 趋势（gpu=B300）。

## 停止条件

四组 B300 TPOT ≤ vLLM，4090 不退化；每轮进 CSV。

## 迭代上限

8 轮。

## 记录

| 轮 | 改动 | 结果 |
|---|---|---|
| 0 | nsys 定位（上表） | 瓶颈 = 小算子串行访存延迟 + decode splits 不足，非 GEMM |
| 1 | rmsnorm / silu / qkv_post 向量化（16 B 读、全部访存一次发出、头/列铺到多 block）；decode splits 上限 8 → 32（目标 2048 block） | B300 c1 TPOT 1.61 → **1.34 ms**（rmsnorm 3.7→2.1 / silu 6.9→1.8 / qkv_post 6.1→2.1 µs）；c8-long 2.37 → 2.46（splits 32 让 merge 2.4→5.4 µs、decode 本体没降：串行依赖链还在） |
| 2 | decode v2 两级预取（下一轮 K/V 读在本轮 softmax 前发出）；merge 全部 split 一次读进寄存器 | nsys：c1 TPOT 1.34 → **1.27 ms**（vLLM 1.2）；c8-long 2.46 → **2.25 ms**（vLLM 1.4；decode 本体 24.8 → 21.6 µs，merge 5.4 → 3.1）。预取只省 2 µs → decode 长序列瓶颈不在 K/V 依赖链。ncu 不可用（`RmProfilingAdminOnly=1`，无 sudo），只能靠 nsys + 推理 |
