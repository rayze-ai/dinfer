# 逐位置对拍：定位"差异从哪来"的方法（Kaon-V3 2026-10-23 沉淀）

> 适用：已经有一个**有权重 + 参照实现（vLLM）**的模型，端到端 logprob/翻转率对不上，需要判断
> "是语义写错了 / 是口径不同 / 还是根本没法定到逐位"。区别于 `model-onboarding.md`
> （那篇讲接新模型的盲区），这篇讲**已经在跑、但数值不齐**时怎么系统地缩小范围。

## 1. 先分清三类差异，别混成一件

| 类型 | 特征 | 处理 |
|---|---|---|
| **口径差异** | 同一输入下，我们的某个中间量系统性偏移；能靠改一个开关消除 | 改成与参照一致（对齐优先） |
| **Kernel 差异** | 同输入、同公式，只有个别元素差 1 ulp（累加顺序） | **不可消除**，只能度量并接受 |
| **放大器** | 上述 1 ulp 经不连续量化（fp8/fp4 KV、激活量化）放大 1e3–1e4 倍 | 不是错，是双方共有的性质 |

判断顺序：**先看放大倍数，再看 1 ulp，最后才怀疑语义。**

## 2. 整跑 vs 单层隔离：两者缺一不可

- **整跑逐层残差流**（各自累积）→ 找**发散起点层**。隔离会把输入强行对齐，**掩盖前层累积**。
  做法：两侧都 dump `L-1..L29`（我们 `--hidden-all`；vLLM patch `DecoderLayer.forward` 取返回值），逐层求相对误差。
- **单层隔离**（灌参照的 `L{l-1}`）→ 找**层内哪一步**。此时 `input_norm` 必须逐位 0，否则注入路径有问题。
- **交叉验证**：若隔离干净但整跑发散的层，差异一定来自**该层的输入**；用"把真实输入差注入参照输入"可量化该层的
  放大倍数（实测某层 3.3e-7 → 5e-3，**约 1.5e4 倍**）。

## 3. A/B 只切一个运行时开关，用同一份二进制

比"改代码重编再跑"干净得多：排除编译差异与轮次漂移。实现方式：kernel 收**运行时参数**（不是 `#if`），
Rust 侧用环境变量选。本次用过的开关：`GELU_F32` / `MOE_COMBINE_F32` / `ROUTER_F32` / `KV_FP8`。
**默认值应等于参照口径**（用户 2026-10-23：「先和 vllm 对齐，精确与否是下一步或开关的事」）。

## 4. 判断"这个差异能不能消除"：直接调参照自己的算子

不要靠读源码推断。做**三方对比**：参照前向的输出 / 参照自己的算子单独跑 / 我们的算子。

实测（Kaon-V3 L0 `q_proj`，同输入同权重）：
- 参照自己调自己的 flashinfer 算子 vs 参照前向：**7/196608**
- 我们 vs 参照前向：**5/98304**
- 参照自家两个 kernel（flashinfer vs cutlass）互比：**10/196608**

**参照自己都做不到单算子复现自己的前向** → 目标不是逐位，而是"差异落在 kernel 变体量级内"。
调用要点：`vllm._custom_ops.cutlass_scaled_mm(a, b, scale_a, scale_b, out_dtype)` 要求 `b` 是**转置视图**
（`b.t().contiguous().t()`）；权重布局上，**checkpoint 是 `[N,K]`，vLLM 加载后是 `[K,N]`** —— 弄错会差 89026/98304
（我犯过，误以为是发现）。

## 5. 确定参照真实命中哪个 kernel（运行时，不是读代码）

- vLLM 的 fp8 linear kernel 由 `init_fp8_linear_kernel(..., force_kernel=...)` 选
  （`model_executor/kernels/linear/__init__.py`），候选含 FlashInfer / Cutlass / Marlin / B12x / Torch。
- 模型实际命中：打印 `type(layer.quant_method.fp8_linear).__name__`（本模型 = `FlashInferFP8ScaledMMLinearKernel`）。
- **强制切换**：建 LLM **之前** patch `init_fp8_linear_kernel` 塞 `force_kernel`；建之后 patch 无效（实测）。

## 6. 数值结论落盘前的前置条件（否则结论会假）

每个读数必须能回答：
1. **同步了吗** —— 改的脚本 `sync` 到远端；容器里 `grep` 确认新代码存在。
2. **A/B 真的不同吗** —— 两次运行的输出 md5 **必须不同**，日志命中标志（如 `picked kernels: {...: 120}`）要对。
3. **环境干净吗** —— 跑前跑后查 `nvidia-smi --query-compute-apps`；自己的残留进程不退会让下一次**静默失败**
   （日志很短、无"写 N 个张量"）。
4. **单次还是多次** —— 同一配置跑两次是否逐位一致（确定性）；不一致时差异多大。

**证据**：`test/kaon3/2026-10-22/kaon3-parity.md` D-1..D-15；`docs/pitfalls.md` 同日两条。
