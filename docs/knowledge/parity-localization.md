# 逐位置对拍：定位"差异从哪来"的方法（Kaon-V3 2026-10-23 沉淀）

> 适用：已经有一个**有权重 + 参照实现（vLLM）**的模型，端到端 logprob/翻转率对不上，需要判断
> "是语义写错了 / 是口径不同 / 还是根本没法定到逐位"。区别于 `model-onboarding.md`
> （那篇讲接新模型的盲区），这篇讲**已经在跑、但数值不齐**时怎么系统地缩小范围。

## 1. 先分清三类差异，别混成一件

| 类型 | 特征 | 处理 |
|---|---|---|
| **口径差异** | 同一输入下，我们的某个中间量系统性偏移；能靠改一个开关消除 | 改成与参照一致（对齐优先） |
| **Kernel 差异** | 同输入、同公式，只有个别元素差 1 ulp（累加顺序） | **不可消除**，只能度量并接受 |
| **放大器** | 上述 1 ulp 经不连续量化（fp8/fp4 KV、激活量化）放大 1e3–1e4 倍 | 不是错，是双方共有的性质 |

判断顺序：**先看放大倍数，再看 1 ulp，最后才怀疑语义。**

> 逐段隔离怎么落地、参照数据怎么先自证：见 [segment-isolation.md](segment-isolation.md)。

## 2. A/B 只切一个运行时开关，用同一份二进制

比"改代码重编再跑"干净得多：排除编译差异与轮次漂移。实现方式：kernel 收**运行时参数**（不是 `#if`），
Rust 侧用环境变量选。本次用过的开关：`GELU_F32` / `MOE_COMBINE_F32` / `ROUTER_F32` / `KV_FP8`。
**默认值应等于参照口径**（用户 2026-10-23：「先和 vllm 对齐，精确与否是下一步或开关的事」）。

> 用参照的中间量做判据之前，必须先做"参照自证"：见 [segment-isolation.md](segment-isolation.md) §2。

## 3. 判断"这个差异能不能消除"：直接调参照自己的算子

不要靠读源码推断。做**三方对比**：参照前向的输出 / 参照自己的算子单独跑 / 我们的算子。

**2026-10-23 修正（这条一度写错，代价是多轮空转）**：Kaon-V3 L0 `qkv_proj` 实测

| 对比 | 差异 |
|---|---|
| 参照同入参重复 6 次（自身确定性）| **0** |
| **参照重调自己的 flashinfer vs 它前向里的真实返回值** | **0 / 196608** |
| flashinfer vs cutlass（同入参）| 7 / 196608 |

→ **"参照自己都做不到单算子复现自己的前向"是错的**。那 7 处是 `fi vs cu` 的**变体间**差，
被误读成了"自复现失败"，于是把"逐位"错误地判为不可达、白绕了好几轮。
**正确判法**：必须**分开测**这两件事——① 同入参重复调同一算子（确定性与自复现）；
② 同入参换算子变体（变体下限）。混在一起比，就会把②读成①。

**结论**：同 kernel 下目标是**逐位 0**；只有换 kernel 变体才允许非 0（7/196608）。
调用要点：`flashinfer_scaled_fp8_mm` 的 `scale_a/scale_b` 必须是 **0 维 tensor**（内部 `assert .numel()==1`），
传 Python `float` 会崩；`vllm._custom_ops.cutlass_scaled_mm(a, b, scale_a, scale_b, out_dtype)` 要求 `b` 是
**转置视图**（`b.t().contiguous().t()`）。权重布局：checkpoint 物理 `[N,K]`，vLLM 加载后以 `[K,N]` **视图**喂给
FlashInfer（实测 `B.stride()==(1,2816)`）——真按连续 `[K,N]` 造数组去比会差 89026/98304（我犯过，误以为是发现）。

**抓对方真实入参再比**：hook 算子入口把 `(A_fp8, B_fp8, scale_a, scale_b)` 原样存盘，比"自己猜怎么量化"可靠得多。
注意容器里持久路径只有 `/w`（见 `infra-b300.md`）。

## 4. 确定参照真实命中哪个 kernel（运行时，不是读代码）

- vLLM 的 fp8 linear kernel 由 `init_fp8_linear_kernel(..., force_kernel=...)` 选
  （`model_executor/kernels/linear/__init__.py`），候选含 FlashInfer / Cutlass / Marlin / B12x / Torch。
- 模型实际命中：打印 `type(layer.quant_method.fp8_linear).__name__`（本模型 = `FlashInferFP8ScaledMMLinearKernel`）。
- **强制切换**：建 LLM **之前** patch `init_fp8_linear_kernel` 塞 `force_kernel`；建之后 patch 无效（实测）。

## 5. 量化器放大倍数不能跨起点比（2026-10-23）

"我们从 L2 起放大倍数是参照的 2–3 倍 ⇒ 我们另有一个放大器"——**这个推断是错的**，已作废。
理由：fp8 的放大倍数 ≈ q/δ 且随 δ 增大而**饱和**（δ≫q 时放大→1）。两边起点差 540 倍
（L0：我们 4.9e-8 vs 参照自家变体 2.65e-5），放大倍数根本不可比。
**判据要看同分母的量**：单算子 vs 各自前向（我们 10/196608、参照 7/196608，同量级），
以及末层是否同处饱和区（都 O(1e-1)）。

## 6. 差 1-ulp 时，先问"参照用的是哪个库"（2026-10-23，Kaon-V3）

我们自写 fp8 GEMM 与 vLLM 差 8/196608 个 1-ulp，追了多轮口径/布局/量化都无功。
真因是**参照根本没用通用 kernel，而是走了 cuBLAS**（FlashInfer 的 `CublasFp8GemmRunner`
→ `cublasLt`），而 cuBLASLt 的**启发式 algo 选择**决定累加序：

| 实现 | vs vLLM |
|---|---|
| 自写 kernel | 8 / 196608 |
| cuBLASLt 启发式 algo[0] / [1] | 8 / 196608 |
| **cuBLASLt algo[2]** | **0 / 196608** |

**方法**：
1. 先用"同入参重复 N 次"证明参照**确定**、且能**自复现**（D-17b：都是 0）；
2. 再枚举 backend（`auto/cublas/cudnn/cutlass`）定位真实库；
3. 定位到库后，**枚举该库的候选 algo**（`cublasLtMatmulAlgoGetHeuristic` 返回多个），
   逐个跑、与参照比——命中的那个就是要固定的。
4. 结果要**写死并附来历注释**（换 CUDA 版本可能变，但参照也会一起变）。

**教训**：自写 kernel 追 1-ulp 的尽头是"复刻闭源代码的舍入"，代价高且脆弱。
**优先检查能否直接调用同一个库**——尤其当参照是 PyTorch/vLLM 这类会落到 cuBLAS 的实现。

## 7. 参照落到同一个第三方库时，用"配置属性"而非"列表下标"选 algo（2026-10-23）

cuBLASLt 的 `cublasLtMatmulAlgoGetHeuristic` 返回**多个**候选，**顺序随形状漂移**：
同一个正确 kernel 在 A 形状排第 0、在 B 形状排第 2。因此

- **不能按下标写死**（我们一度写死 `[2]`，只在一个形状对，其余 5 个形状反而变差，端到端退步 1.24pp）；
- **要按 `CUBLASLT_ALGO_CONFIG_ID / TILE_ID / SPLITK_NUM` 匹配**（`cublasLtMatmulAlgoConfigGetAttribute`
  读出，拼成 `id=67 tile=13 splitk=1` 这样的字符串做索引）。
- 不同形状的"正确配置"可能不同（我们 6 种形状里 5 种共用一套，`K=8192` 需要 split-K 的另一套），
  所以用 **`(n,k) → 配置` 的实测表 + 通配回退**，未命中时用启发式第 0 个（不会更差）。

**通用工具已落地**：`Gemm::forward_fp8_cublaslt_algo` / `forward_bf16_algo` +
`*_algo_count` / `*_algo_desc` + `crates/kernels/tests/{fp8,bf16}_algo_calib.rs`。

**还有一个前置陷阱**：小 M（我们 `m ≤ 32`）会走自写 split-K kernel，**根本到不了 Lt 路径**。
改 Lt 的 algo 选择前必须先确认目标调用走的是哪条分派（`plan_for`）。

## 8. A/B 的对照必须用**真实数据 + 真实调用路径**（2026-10-24）

为了让"要不要写一个新 kernel"这个决定有依据，我曾直接比 `torch.matmul` 与参照的 `matmul_persistent`：
随机正态输入、形状 M×128×2816 → **43% 元素不同**（max 7.8e-3）。
据此判定"router GEMM 必须同源"，写了一个逐位复刻的 kernel（kernel 级 0/8192 ✓），接进去一跑——
**端到端 A/B 逐字节相同**。

回头在同一份**真实 `routed` 输入**上把两条路都跑一遍：**0/3072，逐位相同**。

错在两个地方，都是"看起来严谨"的错：
- **对照选错了**：`torch.matmul` 在 2D 形状上可能选 split-k 或不同 tile，而我们代码里是显式 cuBLASLt + 固定 workspace
  的启发式。**被测的是什么路径，就得用那条路径去比**，不能找"另一个 cuBLAS 入口"代替。
- **数据选错了**：随机正态的动态范围比真实激活大一个量级，两者恰好都舍到同一个 bf16 就不奇怪了。

**规则**：
1. 判"要不要改"，必须用**真实前向里的那份张量**（hook / dump 下来），不能自己造；
2. 对照必须是**被测代码真正走的那个封装**（不是 `torch.*` 的等价 API）；
3. 先做 A/B 的**端到端或至少真实输入**验证，再根据它决定要不要写新实现——顺序反了会白写一遍 kernel。

排查价值仍在（那个 kernel 逐位正确、不依赖 `CUBLASLT_WORKSPACE_SIZE`，留着当更可控的实现），
但**它不是 flip 的来源**，得继续找。

## 9. 先算"精度预算"，再决定查哪一层（否则一直在追 1-ulp 幽灵）

2026-10-24 连续三次踩同一个坑：怀疑某个算子的近似实现（`rcp.approx` vs 精确除法），
改完 A/B 输出**逐字节相同**。三次都是同一个原因，但每次都要跑一轮才发现：

| 位置 | 近似误差 | 下游舍入步长 | 比值 | 结果 |
|---|---|---|---|---|
| router 归一化 `rcp.approx` | 2⁻²³ | bf16 输出 2⁻⁹ | 1/16384 | 被吞 |
| fp4 块缩放 `rcp.approx(6)` | 2⁻²³ | e4m3 块缩放 2⁻⁴ | 1/524288 | 被吞 |

**做法**：动手改之前先写两行算式——**这个近似误差 / 下游第一次舍入的步长**。
- 比值 ≪ 1 → 舍入必然吞掉它，**改了不起作用，别改**；
- 比值 ~1 或更大 → 值得试。

**例外（重要）**：误差小不代表**下游是连续的**。如果下游是**不连续映射**（fp4/fp8 量化、
top-k 选择、argmax），1 ulp 的差可能让元素**跨过舍入中点**，落到相邻的可表示值——
那时比值再小也会放大。判断方法：看下游是否"取整/排序/量化"，而不是"再做一次算术"。
本例中 fp4 元素量化（步长 50%）就是这种放大器，而块缩放 e4m3（步长 12%）不是。

## 10. 对拍必须钉住**同一个 GEMM 实现**（生产默认那条），否则结论反过来

2026-10-26（loop `kaon3-mega` R15）：dense MLP megakernel 在**合成权重**测试里 B=1/2/4/8 全 0 差异，
但接进真实前向后端到端文本 5/5 都不同。真实权重逐段对拍暴露根因：

| 参考路径 | pre_norm | gate | up | gelu | down |
|---|---|---|---|---|---|
| `QLinear::forward` 默认 = **cuBLASLt** | 0 | 4 | 2 | 4 | 122/56320 |
| `FP8_SELF_KERNEL=1` = 自写 tile kernel | 0 | **0** | **0** | **0** | 3 |

即：**kernel 的 fp8 累加序对齐的是自写 kernel，而生产走 cuBLASLt**。合成权重测试之所以"逐位一致"，
是因为它参考路径也调 `gemm.forward_fp8`（自写）——**两边同一个 oracle，测不出跟生产不等价**。

**规则**：写 kernel 对拍测试时，参考路径必须调**生产真实调用的那个封装**
（Kaon 的 FP8 是 `forward_fp8_cublaslt`，不是 `forward_fp8`）。若生产有 A/B 开关（`FP8_SELF_KERNEL`），
**两个都要跑**，并分别记录差异率；只跑一个会把"对齐了备胎"误判成"逐位一致"。

**量级口径**：0.2% 元素差 1 个 bf16 ulp（`max|d|` 在跨零值上会显示很大，要看相对差/ulp 数），
经 30 层累积会让少数近并列 token 翻转 —— 端到端表现为"文本不同但语义等价"，不是质量退化。
